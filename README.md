sec-html-entity
================

评论发布前的清洗服务换了一版实体处理，上线后同一段用户文本在「预览、入库、二次渲染」三处显示不一致，安全团队复核时还发现带引号的属性值可以穿过标签剥离，部分历史工单里出现空白字符与半个代理对。契约要求：实体解码一次且只解一次，命名实体区分大小写，数字实体必须带分号，十进制与十六进制（`x` 与 `X` 均可）都支持，码点为零、落在代理区或超出 Unicode 范围时统一替换为 U+FFFD，无法识别的实体原样保留；转义必须覆盖 `& < >`，双引号与单引号是否转义由调用方显式控制，且转义结果使用固定拼写 `&quot;` 与 `&#39;`；规范化等于「解码一次再转义一次」，重复规范化结果不变，因此双写实体不得被展开成标签；标签剥离必须识别引号内的 `>`，未闭合的 `<` 原样保留；安全判定要先把多层编码反复解到稳定，再做大小写无关的协议检查，并拒绝仍含尖括号的文本。不变量：对任意文本，`canonicalize(canonicalize(x)) == canonicalize(x)`；`decode` 的单次语义不受后续编码层影响；`strip_tags` 的输出不再包含完整标签。
